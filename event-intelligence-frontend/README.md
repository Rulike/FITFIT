# 金融事件智能分析平台前端说明

本目录是一个纯 HTML / CSS / JavaScript 的前端演示工程，配合 `api_server.py` 提供本地预览和 `/api/v1` 接口。页面不依赖 Vue、React 或构建工具，主要用于展示公开金融事件的监测、判断、脉络和预警流程。

## 启动方式

```bash
python api_server.py --host 127.0.0.1 --port 8080
```

访问 `http://127.0.0.1:8080`。登录入口是 `auth.html`，主界面是 `index.html`。演示账号为 `demo@finsight.cn` / `123456`。

## 页面结构

- `auth.html`：账号登录、注册账号、演示账号填充和本地会话保存。
- `index.html`：主工作台骨架，包含侧边栏、顶部栏、内容区、详情抽屉、弹窗和命令面板。
- `app.js`：负责页面路由、数据加载、交互事件、表格/卡片/抽屉渲染。
- `charts.js`：负责趋势图、环形图、火花线和知识图谱绘制。
- `styles.css` / `auth.css`：负责视觉风格和响应式布局。

## 主要功能页

- 概览看板：事件指标、趋势、类型构成、重点事件流。
- 事件监测：关键词、影响等级、情绪筛选和详情抽屉。
- 可信评估：综合评分、证据列表、判断依据。
- 演化追踪：事件时间线、阶段节点、影响变化。
- 预警中心：分层预警、确认处置和规则设置。
- 知识图谱：公司、事件、行业、政策、技术和风险关系。
- 任务链路：按事件选择和任务选择逐步展开处理过程。

## 任务链路说明

任务链路页面对应 `process-demo` 演示数据，核心交互是“先选事件，再选任务”：

1. 先从“事件流队列”下拉框选择一个事件。
2. 未选择事件时，队列区域只显示占位状态，不提前展开后续内容。
3. 选中事件后，任务下拉框才可用。
4. 再选择某个任务阶段后，才加载该阶段的详细信息。
5. 未选中的阶段保持“待选择”状态，不显示下一步任务的完整处理信息。

这个设计是为了模拟“事件还未被处理完成”的演示过程，让处理链路按步骤展开，而不是一开始就把所有结果写满。

## 接口层

前端统一通过 `js/api.js` 访问后端。默认配置如下：

```js
const CONFIG = {
  USE_MOCK: false,
  BASE_URL: '/api/v1',
  TIMEOUT: 12000
};
```

常用接口如下：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/dashboard` | 总览指标、趋势、事件构成和链路状态 |
| GET | `/events` | 事件列表，支持 `query`、`level`、`sentiment` |
| GET | `/events/{id}` | 单个事件详情 |
| GET | `/events/{id}/credibility` | 可信评分、因子和证据矩阵 |
| GET | `/events/{id}/timeline` | 事件阶段与演化时间线 |
| GET | `/knowledge-graph?scope=company` | 图谱节点和关系 |
| GET | `/alerts` | 预警列表 |
| POST | `/alerts/{id}/acknowledge` | 确认处置预警 |
| GET | `/companies/{code}` | 主体信息和趋势 |
| GET | `/models/metrics` | 模型与运行指标 |
| GET | `/workbench` | 工作台汇总数据 |
| GET | `/process-demo?limit=5` | 任务链路演示数据 |
| GET | `/search?q=` | 公司、代码和事件搜索 |
| POST | `/auth/login` | 登录 |
| POST | `/auth/register` | 注册 |
| POST | `/watches` | 新建监控 |

`mock-data.js` 仍保留为离线兜底数据；如果需要纯本地 mock 演示，可以把 `USE_MOCK` 改成 `true`。

## 本地服务说明

`api_server.py` 只使用 Python 标准库，既负责静态文件托管，也负责从上层项目输出中读取数据并组装成前端可消费的 JSON。它适合本地演示和成果包预览，不需要额外安装前端框架或后端依赖。


## 2026-09-16：事件分析流程更新

- 事件监测每页 25 条，支持重置筛选；导出包含全部匹配事件。
- 点击“分析”后进入可信评估，再通过步骤导航查看同一事件的演化与影响、预警跟踪。
- 当前事件保存在地址的 `?event=事件ID` 中；刷新、前进和后退保持对应对象。未选择事件时显示选择入口。
- 可信度展示原始分值与已有等级，与情绪方向、影响级别分开。图谱关联数按当前图统计；未提供的分数不再推算。
- 任务链路是已有结果回放，不会触发在线模型推理。
- 预警按规则阈值生成；确认后进入“跟踪中”，不等同于风险已解除。顶部和导航角标显示待处置数量。
- “保存关注”保存检索条件，可在预警中心的“我的关注”回看；不自动发送通知。

### 状态与接口

运行服务使用 `python3 api_server.py --host 127.0.0.1 --port 8080`。
新增 `workflow_store.py`，仅依赖 Python 自带 SQLite。默认数据库为 `.runtime/workflow.sqlite3`，与模型冻结产物分离，保存预警确认、预警规则和关注条件；重启后保留。可通过 `EVENT_INTELLIGENCE_STATE_DB` 指定独立数据库位置。当前为本地共享工作台，状态不按账号隔离。

新增接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/alert-rules` | 读取预警规则 |
| POST | `/alert-rules` | 保存并应用规则 |
| GET | `/watches` | 读取已保存的关注条件 |

规则字段：`high`、`critical`、`credibility`，均为 0–100 数值，且 `high < critical`。默认 75、90、0；最低可信度 0 表示不限。规则仅影响预警筛选与分级，不改原始影响分和模型输出。平台内显示，无邮件通道。

预警 ID 由事件 ID 生成，事件排序变化不会错绑处置状态。不存在的事件或预警返回 404，不再以第一条事件代替。`.runtime` 等隐藏目录禁止通过静态 GET 下载。

真实数据模式的持久化由服务端提供。`USE_MOCK=true` 仅用于离线演示，状态保存在当前页面内存中，刷新后重置。

### 回归验证

```bash
python3 -m unittest discover -s tests -v
node --check js/app.js
node --check js/api.js
```

浏览器用例位于 `tests/workflow.spec.cjs`，测试依赖为 `@playwright/test`。运行前另开一个使用独立 `EVENT_INTELLIGENCE_STATE_DB` 的测试服务，设置 `FRONTEND_TEST_URL` 指向它，再执行 `playwright test`。浏览器测试会创建确认记录、临时调整规则，不应对正式演示服务运行整套用例。服务须能读取项目事件数据（至少 50 条供分页用例使用）。

本次在 Ubuntu 20.04 使用 Playwright 1.48.2 + Chromium 130 验证；测试工具不属于页面运行依赖。设计和计划见 `docs/superpowers/`。

## 2026-09-17：任务链路与知识图谱布局

- 任务链路回放采用“事件上下文 + 左侧阶段导航 + 右侧当前结果”格式。未选事件时阶段按钮禁用；切换事件会清空上一阶段；页面只展开当前任务的已有结果。
- 知识图谱支持公司关系、事件关系、风险关系范围切换，恢复自由关系图布局；节点可以单独拖动，空白区域可平移，滚轮可缩放，点击节点后右侧显示详情。
- 图谱底部显示当前节点和关系数量，事件节点提供“分析此事件”入口。
- 图谱缩放和重置按钮带有可访问名称；缺失的统计显示“未提供”，不根据节点大小推算。
